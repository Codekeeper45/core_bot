# Neodrain Agent Bot — AI-оркестратор задач

AI-ассистент руководителя в мессенджерах: принимает задачу → анализирует → строит план →
декомпозирует на подзадачи → распределяет между сотрудниками → диспатчит → контролирует
выполнение → отчитывается «кто что сделал». Один агентный цикл с вызовом инструментов
(tool-calling) поверх LLM, три канала связи (WhatsApp / Telegram / Instagram) и реестр
сотрудников в MySQL.

> Не «чат-ассистент-болтун», а **диспетчер команды**: босс ставит цель — бот сам решает, кого
> привлечь, и доводит работу до результата. Сотрудники отчитываются боту в том же мессенджере.

## Как это работает

```
Босс (WhatsApp/Telegram):  «Запусти лендинг под новую серию лотков к пятнице»
        │
        ▼
1. Бот анализирует: масштаб, роли, риски, зависимости
2. list_employees → кто свободен, какие навыки, текущая нагрузка
3. create_project → план + подзадачи (с зависимостями и исполнителями)
4. Показывает план боссу на утверждение  ← КРУПНАЯ задача
5. После «ок» → dispatch_task каждому исполнителю в его мессенджер
        │
        ▼
Сотрудник:  «Сделал макет, отправил на ревью»
        │
        ▼
6. update_task (бот сам сопоставляет с нужной подзадачей) → статус in_progress/done
7. Боссу автоматически прилетает прогресс; project_status — полный отчёт по запросу
```

Для простых поручений («напомни Лене прислать отчёт к 18:00») бот **автоматически** включает
быстрый режим: без декомпозиции и утверждения — сразу создаёт задачу из одного пункта и диспатчит.

## Возможности

| Возможность | Кратко |
|---|---|
| **Планирование и декомпозиция** | Из одной цели — план с подзадачами, зависимостями (DAG), исполнителями за один вызов |
| **Делегирование** | Диспатч подзадач сотрудникам в их канал; гейт по незавершённым зависимостям |
| **Контроль и отчётность** | Приём отчётов от сотрудников, авто-уведомления боссу, сводный `project_status` |
| **Два режима** | Сообщение от босса → оркестрация; от сотрудника → приём отчёта (определяется по реестру) |
| **Быстрый режим** | Простое поручение → 1 задача + мгновенный диспатч, без церемоний (определяется автоматически) |
| **Реестр сотрудников** | В MySQL; импорт из Excel; правка из чата (`manage_employees`) |
| **Фильтр доступа** | Отвечает только сотрудникам и боссам; посторонние молча игнорируются |
| **3 канала** | WhatsApp (Baileys), Telegram (Telegraf), Instagram Direct (Wazzup24) — единый формат |
| **Мультимодальность** | Голос → текст (STT), изображения → описание (Vision), документы → текст (PDF/DOCX/XLSX/TXT) |
| **Память диалога** | История в MySQL + авто-сжатие старого контекста в сводку; сброс командой `/new` |
| **Авто-эхо действий** | Босс видит в чате, какой инструмент вызвал бот и что делает (`ECHO_TOOL_CALLS`) |
| **LLM с fallback** | DeepSeek → OpenRouter primary → OpenRouter backup, ретраи на каждом |
| **Удалённая привязка WA** | HTTPS-страница `/pair` (QR + код) через Cloudflare-туннель — без доступа к серверу |

## Архитектура

Каждое входящее сообщение проходит конвейер (`src/index.js`):

```
Входящее (WA / TG / IG)
        │
        ▼
1. normalize       → единый объект {channel, chat_id, phone, message_type, ...}
2. access-фильтр   → не сотрудник и не босс → молча игнор (RESTRICT_TO_KNOWN_SENDERS)
3. команды         → /new и синонимы очищают историю чата
4. media           → голос→STT, изображение→Vision, документ→текст
5. buffer          → склейка быстрых сообщений (~1с)
6. rate-limit      → ≤10 сообщений/мин на чат
7. dedup           → гасит повторы webhook'ов
8. concurrency     → один запрос на чат, остальное в очередь
9. AI-агент        → LLM + tool-calling (11 инструментов), до 20 итераций
10. sendReply      → ответ обратно в исходный канал (без Markdown и таблиц)
```

## Быстрый старт

### Требования

- **Node.js** ≥ 18
- **MySQL** 5.7+ / 8.x
- API-ключ **OpenRouter** (нужен всегда — STT/Vision; и как минимум fallback для текста)
- (Опц.) ключ **DeepSeek** — как основной текстовый провайдер
- Токен **Telegram-бота** и/или привязка WhatsApp / Instagram

### Установка

```bash
git clone https://github.com/Codekeeper45/Neodrain_agent_bot.git
cd Neodrain_agent_bot
npm install
cp .env.example .env
```

Минимум в `.env`:

```bash
OPENROUTER_API_KEY=sk-or-...        # LLM + STT + Vision
MYSQL_HOST=localhost
MYSQL_DATABASE=botdb
MYSQL_USER=botuser
MYSQL_PASSWORD=...
TELEGRAM_BOT_TOKEN=123456:ABC...    # хотя бы один канал
BOSS_CONTACTS=77071234567           # номера/chat_id боссов через запятую (ВАЖНО!)
```

> ⚠️ При включённом фильтре доступа (`RESTRICT_TO_KNOWN_SENDERS=1`, по умолчанию)
> **обязательно** задайте `BOSS_CONTACTS` — иначе босса примут за постороннего и
> проигнорируют. Бот предупредит об этом в логах при старте.

### Запуск

```bash
npm start            # = node src/index.js
```

При старте бот:
1. Создаёт 5 таблиц в MySQL (если их нет) и импортирует реестр сотрудников из Excel (если есть файл).
2. Поднимает Telegram (polling или webhook).
3. Подключается к WhatsApp (если есть сессия) или ждёт привязки через `/pair`.
4. Регистрирует Wazzup-webhook (если настроен Instagram).
5. Поднимает HTTP-сервер: `GET /health`, страница `/pair`.

Проверка: `curl http://localhost:3000/health` → `{"status":"ok","mysql":"connected",...}`.

### Запуск через Docker (с MySQL «из коробки»)

```bash
cp .env.example .env     # заполните OPENROUTER_API_KEY, BOSS_CONTACTS, токены каналов;
                         # MYSQL_HOST оставьте = mysql (имя сервиса в compose)
docker compose up --build
```

Сессия WhatsApp (`auth_info_baileys/`) и данные MySQL хранятся в volume и переживают рестарт.

## Два режима: босс и сотрудник

Режим выбирается автоматически в `systemPrompt.js` по тому, **кто пишет**:

- **Сообщение от босса** (номер в `BOSS_CONTACTS`, либо не сотрудник на WhatsApp) →
  **режим оркестрации**: анализ → план → делегирование → контроль. Босс — администратор
  системы: видит и управляет ВСЕМИ планами и задачами, кем бы они ни были созданы.
- **Сообщение от сотрудника** (есть в реестре `orch_employees`) → **режим приёма отчёта**:
  бот трактует сообщение как апдейт по одной из открытых задач сотрудника, вызывает
  `update_task`, а вопросы/проблемы, которые сам не решает, передаёт боссу через `message_boss`.

Внутри режима босса бот сам определяет масштаб:
- **Простая повседневная задача** → быстрый режим (1 задача + мгновенный диспатч, без утверждения).
- **Крупная / сложная / рискованная** → полный пайплайн с планом и шагом утверждения.

> Стиль ответов: без Markdown и таблиц (мессенджеры их ломают) — короткие строки и списки.
> Результат планирования бот называет боссу **планом** (не «проектом»).

## Инструменты агента

11 инструментов (`src/tools/`, автозагрузка через registry). Босс пользуется планированием и
контролем, сотрудник — отчётностью.

| Инструмент | Кто | Назначение |
|---|---|---|
| `list_employees` | босс | Реестр сотрудников: роли, навыки, нагрузка + открытые задачи (id) каждого |
| `create_project` | босс | Создать план с подзадачами, зависимостями и исполнителями за один вызов |
| `assign_task` | босс | Назначить/переназначить подзадачу (при блокировке/перегрузке) |
| `dispatch_task` | босс | Отправить подзадачу исполнителю в его канал (гейт по зависимостям) |
| `project_status` | босс | Статус плана со сводкой; без `project_id` — ВСЕ планы системы |
| `revise_project` | босс | Пересмотреть план по возражению/фидбэку: правки, новые задачи, переназначения |
| `update_task` | оба | Сменить статус/записать результат подзадачи (сотрудник — свою; босс — любую) |
| `message_employee` | босс | Быстрое сообщение сотруднику(ам) вне задачи: по id/имени/роли, можно всем по роли |
| `message_boss` | сотрудник | Переслать боссу вопрос/проблему/возражение, требующие решения руководителя |
| `manage_employees` | босс | Правка реестра из чата: добавить/изменить/удалить сотрудника |
| `get_current_time` | оба | Текущие дата/время (UTC) для проставления сроков |

## Реестр сотрудников

Хранится в таблице `orch_employees` (`id, name, roles, skills, channel, contact, active`).

- **Первичный импорт из Excel** (`src/services/employeeImport.js`): файл
  `Структура Неодрэйн.xlsx` (или `EMPLOYEE_FILE`) в корне проекта. Колонки:
  `ФИО → name`, `Должность → roles`, `Роль → skills`, `Телефон → contact`. Телефон
  нормализуется (KZ `8…` → `7…`). Импорт **идемпотентный**: если в таблице уже есть хоть один
  сотрудник с контактом — импорт пропускается.
- **Правка из чата:** босс шлёт изменения по штату → бот вызывает `manage_employees`.
- Сотрудник без контакта = «тестовый»: задача ему запишется, но физически не отправится.

> Файл реестра содержит ПД (ФИО + телефоны) и исключён из git (`*.xlsx` в `.gitignore`).
> Держите его только на сервере.

## Подключение каналов

### Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) → токен.
2. `TELEGRAM_BOT_TOKEN=...` в `.env`.
3. Запуск — по умолчанию long polling, сразу готов.
4. (Опц.) `TELEGRAM_WEBHOOK_URL=https://домен` → бот сам зарегистрирует `POST /webhook/telegram`.

### WhatsApp + удалённая привязка `/pair`

WhatsApp через [Baileys](https://github.com/WhiskeySockets/Baileys) (WebSocket-клиент).

- **Локально:** запустите бота → отсканируйте QR из консоли в *WhatsApp → Связанные устройства*.
  Сессия сохранится в `auth_info_baileys/`.
- **Удалённо (заказчик привязывает сам):**
  1. `PAIR_TOKEN=$(openssl rand -hex 16)` и `ENABLE_TUNNEL=1` в `.env`.
  2. Запуск → в логах появится `PAIR PAGE: https://<random>.trycloudflare.com/pair?token=...`.
  3. Отправьте ссылку заказчику → он привязывает по 8-значному коду или QR.

> Сессию нельзя запускать в двух инстансах одновременно с одними креденшелами — WhatsApp
> разлогинит. `auth_info_baileys/` в `.gitignore`.

### Instagram (Wazzup24)

Instagram Direct идёт через агрегатор [Wazzup24](https://wazzup24.com):
1. Подключите Instagram-канал в Wazzup → `WAZZUP_API_KEY` + `WAZZUP_IG_CHANNEL_ID`.
2. `WAZZUP_WEBHOOK_SECRET=$(openssl rand -hex 32)`.
3. Если Wazzup блокирует `*.trycloudflare.com` — поднимите прокси из
   [`cloudflare-worker/`](cloudflare-worker/README.md) и задайте `WAZZUP_WORKER_URL`.

## Эксплуатация

- **Команды в чате:** `/new` (синонимы `/новый`, `/reset`, `/сброс`, `/clear`, `/очистить`) —
  очистить историю переписки чата и начать новую задачу. Планы и задачи при этом сохраняются.
- **Health-check:** `GET /health` → статус, uptime, память, коннект к MySQL, метрики агента.
- **Авто-эхо:** при `ECHO_TOOL_CALLS=1` босс видит действия бота прямо в чате.
- **Graceful shutdown** по `SIGINT`/`SIGTERM`; WhatsApp переподключается после обрыва (кроме logout).

### Ключевые константы (`src/config.js`)

```
BUFFER_WAIT: 1000              окно склейки сообщений (мс)
AI_MAX_ITERATIONS: 20          макс. раундов tool-calling
CHAT_MEMORY_WINDOW: 100        сообщений из MySQL в контекст
CONTEXT_SUMMARY_CHAR_LIMIT: 50000   порог сжатия истории
CONTEXT_KEEP_RECENT_MSGS: 20   дословно хранимых последних сообщений
DAILY_IMAGE_LIMIT / DAILY_DOC_LIMIT: 10
```

## Расширение

Четыре точки расширения (подробнее — [EXTENDING.md](EXTENDING.md), [AGENTS.md](AGENTS.md)):

1. **Поведение / личность** → `src/agent/prompts/system_prompt.txt`.
2. **Новый инструмент** → один файл в `src/tools/` с `{ definition, handler }`; registry
   подхватит автоматически, `agent.js` править не нужно.
3. **Новый канал** → адаптер в `src/channels/` + ветка в `normalize.js` и `sendReply()`.
4. **Модель / провайдер** → через `.env`.

### Tool registry: добавить инструмент = один файл

```js
// src/tools/getWeather.js
'use strict';

const definition = {
  type: 'function',
  function: {
    name: 'get_weather',
    description: 'Возвращает погоду в городе. Зови, когда спрашивают погоду.',
    parameters: {
      type: 'object',
      properties: { city: { type: 'string', description: 'Город' } },
      required: ['city'],
    },
  },
};

// context = { channel, chatId, phone, clientName }
async function handler(args, context) {
  return { city: args.city, temp: '+5°C' };
}

module.exports = { definition, handler };
```

Проверка, что инструмент подхватился:
```bash
node -e "console.log(require('./src/tools').tools.map(t => t.function.name))"
```

> В Claude Code есть slash-команда **`/add-tool`** — опишите инструмент словами, она
> сгенерирует файл по канону registry.

## FAQ

**Бот не отвечает боссу — в логах `[Access] Игнор постороннего`.** Не задан или не совпадает
`BOSS_CONTACTS`. Укажите номер/chat_id босса (только цифры, через запятую) и перезапустите.

**Бот не стартует с ошибкой про MySQL.** Это валидация: заполните `MYSQL_*` в `.env`.

**WhatsApp отвалился после рестарта.** Сессия в `auth_info_baileys/` (в `.gitignore`). Если папка
пуста — привяжите заново через `/pair` или QR. Не запускайте две копии с одной сессией.

**Страница `/pair` отдаёт 503.** Не задан `PAIR_TOKEN` (нужно 16+ символов).

**Как сменить модель LLM?** `OPENROUTER_MODEL` / `DEEPSEEK_MODEL` в `.env`. Модель должна
поддерживать function calling.

**Бот пишет таблицы кашей в мессенджере.** Он не должен — запрет в промпте + backstop
`flattenTables()` в санитайзере превращает таблицы в строки.
